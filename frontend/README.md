# Работяги · Frontend

React + TypeScript + Vite. Приложение работает только с API: демо, переключение ролей и локальное хранение заявок удалены. Роль и разрешённые операции определяет сервер.

## Запуск через Compose

Из корня репозитория:

```sh
docker compose up -d --build
```

Открыть http://localhost:3000. Compose собирает фронтенд и API, запускает PostgreSQL. Nginx раздаёт интерфейс и проксирует `/api` в API. Миграции применяются при старте API автоматически.

Переменные корневого `.env`: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `FRONTEND_PORT` (по умолчанию 3000). Для существующего volume базы используйте прежние учётные данные. Фото сохраняются в `report_photos`, ключи cookie — в `identity_keys`, база — в `postgres_data`. `docker compose down` сохраняет данные; `down -v` удаляет volumes.

При старте сидер создаёт пользователей `user@mail.ru`, `worker@mail.ru`, `dispatcher@mail.ru`, `admin@mail.ru`, `superadmin@mail.ru`. Пароль у всех — `Wertukan!234`. Повторный запуск не создаёт дубликаты, но приводит пароль и роль этих пяти аккаунтов к указанным значениям. Остальные аккаунты не меняются. Обычная регистрация создаёт клиента; суперадминистратор назначает роли в разделе «Пользователи». После смены роли пользователь входит заново.

Для ошибки `ENOTFOUND registry.npmjs.org` настроен `build.extra_hosts` только для сборки фронтенда. IP можно переопределить через `NPM_REGISTRY_IP` (сейчас `104.16.24.34`); HTTPS проверяется. После исправления DNS Docker запись можно убрать. IP CDN может меняться.

Логи: `docker compose logs -f frontend rabotyagi`. Healthcheck фронтенда проверяет Nginx. Если API не запустился из-за миграций или сидера, причину видно в его логах.

## Возможности

- Клиент: регистрация, вход, профиль, адрес, смена пароля; создание заявки с названием, адресом и временем; редактирование описания до публикации; просмотр статуса, отчёта и обсуждения.
- Работяга: открыть или закрыть слот, взять доступную заявку, отметить начало работы, отправить отчёт с тремя подтверждениями и 1–4 фотографиями, исправить отчёт после возврата.
- Диспетчер: список специалистов, доступность и активные заявки; телефонная связь и обсуждение заявки; назначение доступного исполнителя; просмотр, приёмка и возврат фотоотчёта.
- Администратор: модерация, публикация или отклонение заявки; закрытие после приёмки диспетчером.
- Суперадминистратор: действия администратора и диспетчера, список и поиск пользователей, назначение одной основной роли, блокировка и разблокировка аккаунтов.

Очередь фильтруется и ищется по загруженным заявкам. Доступна загрузка следующих страниц. Короткий номер в интерфейсе — первые восемь символов настоящего ID заявки. Обновление очереди — каждые 15 секунд, обсуждения — каждые 10 секунд; доступна ручная перезагрузка. Обсуждение показывает последние 100 сообщений. Статистика относится к загруженным заявкам.

Фотографии сжимаются в браузере и отправляются `multipart/form-data`. API проверяет размер и сигнатуру JPG/PNG/WebP, выдаёт фото только авторизованным участникам по правилам доступа к заявке. Адрес сохраняется в заявке текстовым снимком: последующая смена адреса профиля не меняет новые заявки.

## Локальная разработка

Node.js 24+, pnpm:

```sh
cd frontend
pnpm install
pnpm dev
```

Открыть http://127.0.0.1:5173. Vite проксирует `/api` на http://localhost:5160. Для API из Compose задать `API_PROXY_TARGET=http://localhost:5000` в `frontend/.env.local`. Пример переменных — `.env.example`.

```sh
pnpm build
pnpm test
pnpm format
```

## Структура

- `src/LiveWorkspace.tsx` — вход, регистрация, формы адреса и пароля.
- `src/ConnectedDashboard.tsx` — очередь, рабочие слоты, команда, качество, пользователи, карточка и обсуждение заявки.
- `src/OrderDialogs.tsx` — создание заявки и фотоотчёт.
- `src/api.ts` — DTO и HTTP-клиент с cookie.
- `src/domain.ts` — типы и подписи интерфейса.
- `src/components.tsx`, `src/styles.css` — общие компоненты и адаптивность.

Актуальные маршруты и права: [BACKEND_CONTRACT.md](BACKEND_CONTRACT.md). Серверные проверки: [tests/WorkflowChecks](../tests/WorkflowChecks/README.md).

## Проверка

API и production-фронтенд собираются. Серверный процесс проверен на отдельной временной PostgreSQL-базе: роли, cookie, создание и модерация, конкурентное взятие, слот, фотоотчёт, доработка, приёмка, закрытие, права доступа и блокировка. Через браузер пройден полный цикл с загрузкой фото и сообщением. Проверены мобильные формы и адаптивная сетка. Скриншоты [desktop](docs/desktop.png) и [mobile](docs/mobile.png) сделаны на временной тестовой базе; приложение не содержит этих данных.

Docker CLI в среде агента отсутствует: сборка контейнеров после изменений не проверена. Обычная .NET-сборка, миграции на настоящем PostgreSQL и фронтенд проверены отдельно.
